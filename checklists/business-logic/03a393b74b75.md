## Use case

The KYC verification flow was vulnerable due to the application trusting client-side state, allowing an attacker to manipulate verification flags and bypass security checks, which could lead to unauthorized access to sensitive operations.

## Steps to test

1. Start the onboarding process of the financial application.
2. Use an intercepting proxy to capture the API response containing the verification state.
3. Modify the response to set all verification flags to true, e.g., { 'mobileVerified': true, 'identityVerified': true, 'taxIdValidated': true, 'videoVerificationRequired': false, 'personalDetailsCaptured': true, 'customerExists': true }.
4. Forward the modified response to the application.
5. Observe if the onboarding process skips the KYC steps and allows progression to the payment stage.
