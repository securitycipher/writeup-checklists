## Use case

State-change endpoints such as coupons and checkout processes were vulnerable due to missing database row-locking, allowing for potential race conditions that could exploit the system's logic.

## Steps to test

1. Identify state-change endpoints in the application (e.g., checkout, coupon application).
2. Simultaneously send multiple requests to the endpoint to change the state (e.g., apply a coupon or claim a balance).
3. Monitor the responses to check if the state changes are processed correctly or if they allow for multiple claims.
4. Analyze the database to confirm if the changes were applied correctly or if race conditions occurred.
