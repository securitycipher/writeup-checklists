## Use case

The vulnerability arises from a sequence of valid requests that the application was not designed to handle in that specific order, leading to unintended consequences. This matters because it can allow attackers to exploit the application in ways that automated scanners cannot detect.

## Steps to test

1. Identify a feature that relies on a sequence of user actions.
2. Perform the actions in the expected order to see the normal behavior.
3. Alter the order of these actions and observe if the application behaves unexpectedly.
4. Document any unintended access or actions that can be performed due to this altered sequence.
