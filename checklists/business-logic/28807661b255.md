## Use case

The vulnerability existed in the asynchronous payment processing flow, where the backend did not properly validate payment status notifications from the payment gateway. This allowed an attacker to manipulate payment statuses and potentially bypass payment requirements.

## Steps to test

1. Identify the webhook endpoint used for processing payment notifications, typically found in the application settings.
2. Simulate a payment event by crafting an HTTP POST request to the webhook endpoint with manipulated payload data, such as changing the payment status to 'completed' for a transaction that was not actually completed.
3. Observe the response from the server to confirm if the account status was updated without proper validation.
4. Repeat the process with different payment amounts and statuses to test for other potential bypass scenarios.

## Commands

```text
POST https://example.com/webhook/payment-status
Content-Type: application/json
Body: {"status": "completed", "amount": 500, "transaction_id": "fake_transaction_id"}
```
