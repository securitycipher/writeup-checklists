## Use case

The application allowed users to bypass email blacklisting by exploiting email normalization and using alternative domains from the same provider, which could lead to unauthorized account creation.

## Steps to test

1. Identify the email blacklisting feature of the application.
2. Attempt to register with a blocked email address (e.g., example@proton.me) and confirm the rejection.
3. Analyze the API endpoint for registration (e.g., POST /api/v1/init) and test with a normalized email format (e.g., e.x.ample@proton.me).
4. If the normalized email is accepted, proceed to request the OTP.
5. Use the same normalized email format in the account creation endpoint (e.g., POST /api/v1/auth) with the OTP received.
6. Confirm successful account creation despite the original email being blocked.
