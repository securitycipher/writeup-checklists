## Use case

The application allows cross-origin requests without proper validation of the Origin header, enabling an attacker to exploit this misconfiguration to access sensitive data using the victim's cookies.

## Steps to test

1. Log into the target application and obtain a valid session cookie.
2. Use Burp Repeater to send a request to the vulnerable endpoint (e.g., /accountDetails) with a custom Origin header set to a malicious domain.
3. Set the withCredentials flag to true in the request.
4. Observe the server's response for Access-Control-Allow-Origin and Access-Control-Allow-Credentials headers.
5. If the server responds with Access-Control-Allow-Origin: <malicious_origin> and Access-Control-Allow-Credentials: true, proceed to create a malicious page to exploit the vulnerability.
6. Use XMLHttpRequest in the malicious page to send a request to the target endpoint and capture the response.
