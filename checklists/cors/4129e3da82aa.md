## Use case

The application improperly configures CORS by reflecting the Origin header in the Access-Control-Allow-Origin response without validation. This allows an attacker to read sensitive user data from authenticated requests.

## Steps to test

1. Identify an authenticated endpoint that returns sensitive data (e.g., /api/me, /api/account).
2. Craft a request to the endpoint and add a custom Origin header (e.g., 'Origin: http://malicious-website.com').
3. Send the request and observe the response headers for Access-Control-Allow-Origin.
4. Check if Access-Control-Allow-Credentials is set to true.
5. If the Access-Control-Allow-Origin reflects the crafted Origin, proceed to create a malicious page to exploit the CORS misconfiguration.

## Commands

```text
curl -X GET 'https://example.com/api/me' -H 'Origin: http://malicious-website.com'
curl -X GET 'https://example.com/api/account' -H 'Origin: http://malicious-website.com'
```
