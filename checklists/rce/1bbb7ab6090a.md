## Use case

The application exposed a public API endpoint that allowed unauthenticated users to filter data using relational filters, which inadvertently disclosed private fields of administrator accounts. This led to a chain of vulnerabilities that allowed an attacker to recover a reset password token and execute arbitrary JavaScript on the server.

## Steps to test

1. Send a GET request to /blog-ens to identify the public endpoint.
2. Use the filter parameter to probe for admin-related fields by sending a request like GET /blog-ens?_where[created_by.id]=2.
3. Test for the existence of the reset password token by sending a request with _where[created_by.resetPasswordToken_null]=false and check the response.
4. Perform a binary search to recover the reset password token by iteratively testing values with _where[created_by.resetPasswordToken_gt]=<PROBE>.
5. Once the token is recovered, send a POST request to /admin/reset-password with the recovered token and a new password to gain administrator access.
6. Verify the administrator access by sending a GET request to /admin/users/me and checking for a 200 OK response.
