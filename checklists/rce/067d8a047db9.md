## Use case

The vulnerability arises from unclaimed GitHub usernames that allow an attacker to register them and host malicious code, which can be executed on self-hosted servers when plugins are installed. This is critical as it can lead to full server compromise without any complex exploit chain.

## Steps to test

1. Clone the official plugin registry using 'git clone --depth=1 https://github.com/[target]/all-the-plugins'.
2. Extract all referenced usernames from the registry file using 'grep -oP '^[^/]+' third-party.txt | sort -u > usernames.txt'.
3. Check each username against the GitHub API to identify unclaimed usernames using 'while read username; do status=$(curl -sI "https://github.com/$username" | grep HTTP | awk '{print $2}'); echo "$username: $status"; done < usernames.txt | grep 404'.
4. Verify that the unclaimed usernames are freely registerable by executing 'curl -s "https://api.github.com/users/[username]"'.
5. Confirm that the repositories still redirect by checking the status of each plugin repository with 'curl -sI "https://github.com/[plugin]" | grep -E "HTTP|location"'.
6. Register one of the unclaimed usernames and create a repository with malicious code to intercept the redirect.
