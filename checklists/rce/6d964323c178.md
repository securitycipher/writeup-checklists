## Use case

The article describes a vulnerability in an unauthenticated file upload feature that allows path traversal, leading to remote code execution through cron job processing of uploaded files. This is critical as it enables an attacker to execute arbitrary commands on the server without needing to control the filename or access the uploaded file directly.

## Steps to test

1. Identify an unauthenticated file upload endpoint that accepts a destination directory.
2. Send a POST request to the upload endpoint with a multipart form-data payload containing a benign file and a controlled uploadPath parameter with traversal sequences (e.g., uploadPath=../temp).
3. Observe the response to confirm that the upload was successful and check if the path reflects the traversal.
4. Test writing to sensitive directories (e.g., /etc/cron.d) by appending traversal sequences to the uploadPath parameter.
5. Verify if the backend process has elevated privileges by checking the response for directory creation errors in restricted paths (e.g., /proc).
6. Create a file with cron job syntax in a directory processed by cron to trigger remote code execution.

## Commands

```text
POST /app/api/files/upload HTTP/1.1
Host: host.redacted
Content-Type: multipart/form-data; boundary=X
--X
Content-Disposition: form-data; name="file"; filename="bugbounty-probe.txt"
Content-Type: text/plain
bugbounty benign marker no-script
Content-Disposition: form-data; name="uploadPath"
temp
--X--
```
