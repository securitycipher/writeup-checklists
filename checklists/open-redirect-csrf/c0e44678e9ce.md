## Use case

The application allowed an open redirect through the 'ReturnUrl' parameter without proper validation, combined with a CSRF vulnerability that enabled an attacker to force a victim to log in as the attacker.

## Steps to test

1. Clear all cookies to ensure no authentication tokens are present.
2. Attempt to access the vulnerable endpoint with a crafted URL containing the 'ReturnUrl' parameter set to a malicious site.
3. Observe that the application does not validate the 'ReturnUrl' and allows redirection.
4. Create a CSRF payload that triggers the login action and redirects the victim to the attacker's account.

## Commands

```text
GET https://example.com/vulnerable-endpoint?ReturnUrl=https://malicious-site.com
```
