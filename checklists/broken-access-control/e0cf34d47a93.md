## Use case

The vulnerability allowed an attacker to access and share sensitive files belonging to other users by manipulating the itemid and ownerid parameters. This could lead to unauthorized access to private data and impersonation of users.

## Steps to test

1. Create two user accounts on the target application.
2. Identify the share functionality and note the parameters itemid and ownerid used in the request.
3. Share a file from the first account and capture the request to see the itemid and ownerid values.
4. Modify the itemid and ownerid in the request from the second account to match those of the first account and resend the request to share the file.
5. Observe if the file is successfully shared to the second account, indicating an IDOR vulnerability.
6. Attempt to brute force other itemid values by incrementing the last few digits and resending the requests while monitoring for rate limits.

## Commands

```text
curl -X POST 'https://example.com/share' -H 'Content-Type: application/json' -d '{"itemid": "<itemid_value>", "ownerid": "<ownerid_value>"}'
curl -X POST 'https://example.com/share' -H 'X-Forwarded-Host: 127.0.0.1' -H 'Content-Type: application/json' -d '{"itemid": "<brute_forced_itemid>", "ownerid": "<ownerid_value>"}'
```
