## Use case

The application allowed users to access resources belonging to other organizations due to a flawed client-side encryption mechanism that did not enforce proper authorization checks on the organization identifier.

## Steps to test

1. Authenticate to the application and capture the requests using a proxy.
2. Identify the Org_id header in the requests and note its value.
3. Analyze the JavaScript files to locate the encryption logic for the Org_id value, specifically looking for CryptoJS AES-CBC usage.
4. Recreate the encryption logic in a script using the same key generation method based on the user's JWT token.
5. Modify the Org_id value to a different organization identifier and encrypt it using your script.
6. Replace the original Org_id value in the request with the newly encrypted value.
7. Send the modified request and observe the response for unauthorized data access.

## Commands

```text
curl -X GET 'https://example.com/api/resource' -H 'Authorization: Bearer <JWT_TOKEN>' -H 'Org_id: <ENCRYPTED_ORG_ID>'
```
