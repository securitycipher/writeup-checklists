## Use case

The vulnerability was found in a recruiting SaaS platform where an unauthenticated user could manipulate a UUID in the URL to access and modify another company's data, leading to a cross-tenant credential leak.

## Steps to test

1. Identify the endpoint GET /api/integrations-proxy/connections?orgId=<my-org-guid> and observe the response.
2. Find an unauthenticated endpoint GET /api/auth/ssoEmail?email=anyone@target-company.com to retrieve a target company's orgId.
3. Replace <my-org-guid> in the original request with the retrieved <target-company-org-guid> and send the request.
4. Observe the response containing the target company's connection records and credentials.
5. To test write access, send a POST request to /api/integrations-proxy/connections?orgId=<target-company-org-guid> with a new connection record.
6. Verify the creation by sending a GET request to the connections endpoint again to see the new record.
7. To test deletion, send a POST request with the existing record's ID and set isDeleted to true.
