## Use case

The vulnerability exists in a multi-tenant SaaS platform where an attacker can exploit a lack of proper path normalization to access another tenant's resources. This is critical as it allows unauthorized access to sensitive data across different tenants.

## Steps to test

1. Create two separate companies (A and B) in the application.
2. Attempt to access a resource from company A using the endpoint GET /api/companies/115374/resources/rules/12225249/body and confirm it returns a 403 Forbidden.
3. Attempt to access the same resource from company B using the endpoint GET /api/companies/115375/resources/rules/12225249/body with the parameter relative_entity_path set to ../115374/projects/396367/master_rules/28132172.
4. Confirm that this request returns a 200 OK response, indicating successful unauthorized access to company A's resource.
