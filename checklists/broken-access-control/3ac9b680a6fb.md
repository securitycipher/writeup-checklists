## Use case

The password reset functionality allowed an attacker to change another user's password without any authentication or verification, leading to potential mass account takeover.

## Steps to test

1. Identify the password reset endpoint, e.g., POST /users/resetPassword.
2. Send a request with a valid User_Id and New_Password in the body.
3. Remove any authentication headers such as Authorization: Bearer <JWT>.
4. Modify the User_Id parameter to a different user's ID.
5. Send the modified request and observe the response.
6. Attempt to log in with the new password for the modified User_Id.
