## Use case

The vulnerability allowed an authenticated user to access another tenant's private account data due to improper caching of authorization decisions in an API Gateway. This misconfiguration led to unauthorized data exposure without requiring elevated permissions.

## Steps to test

1. Obtain an authenticated token for account A.
2. Make a request to access account B's data: GET /accounts?account_id=<B> and verify it returns 403.
3. Make a request to access account A's own data: GET /accounts?account_id=<A> and verify it returns 200.
4. Now, make a request to access account B's data again: GET /accounts?account_id=<B> and verify it returns 200, exposing B's private data.
5. To confirm the cache issue, make a request to access account B's data first: GET /accounts?account_id=<B> and verify it returns 403.
6. Finally, make a request to access account A's own data again: GET /accounts?account_id=<A> and verify it returns 403.
