## Use case

Insecure Direct Object Reference (IDOR) vulnerabilities allow unauthorized access to sensitive data by manipulating object identifiers in requests. This can lead to data exposure or unauthorized actions on behalf of other users.

## Steps to test

1. Register two accounts (Account A and Account B) on the target application.
2. Use Burp Suite to capture requests while navigating through the application as Account A, noting all object identifiers (IDs) in requests.
3. Log in as Account B and retrieve its object IDs, then switch back to Account A's session in Burp Repeater and replace the IDs with those from Account B.
4. Send the modified request and check the response; if it returns sensitive data from Account B, the IDOR vulnerability is confirmed.
5. Repeat the process for different HTTP verbs (GET, POST, DELETE, PATCH) to check for consistent access control failures.
