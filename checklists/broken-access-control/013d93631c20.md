## Use case

The vulnerability exists in a permissions endpoint that improperly handles user IDs, allowing an attacker to bypass ownership checks and access sensitive information from other tenants. This can lead to unauthorized access to personally identifiable information (PII) and manipulation of access control lists (ACLs).

## Steps to test

1. Identify the permissions endpoint: POST /rpc/api.php.
2. Attempt to add a user from another tenant by sending a request with 'user_group_id': 'victim_id'.
3. Observe the response, which should indicate access denial.
4. Modify the request to send two user IDs separated by a comma: 'user_group_id': 'victim_id,tenant_user_id'.
5. Send the modified request and confirm it is accepted.
6. Call the companion method to read back the folder's ACL: POST /rpc/api.php with 'method': 'getObjectAcl' and 'data': [{'id': 'FOLDER_ID'}].
7. Check the response for unauthorized PII disclosure.
