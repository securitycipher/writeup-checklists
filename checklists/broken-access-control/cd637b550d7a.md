## Use case

The vulnerability allowed an authenticated user to change the uid parameter in a registration request, leading to unauthorized account modifications and full account takeover. This was possible due to a lack of proper authorization checks on the server side.

## Steps to test

1. Register as a normal user to create Account A.
2. Intercept the registration request using Burp Suite.
3. Change the uid parameter from your user ID to the target user's ID.
4. Send the modified request to the server.
5. Set a new password for the target account in the same request.
6. Log in to the target account using the new password.
