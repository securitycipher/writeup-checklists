## Use case

The article discusses how improper handling of HTTP methods can lead to vulnerabilities such as IDOR, where an attacker can manipulate HTTP methods to bypass authorization checks and access or modify resources they should not have access to.

## Steps to test

1. Identify an endpoint that uses different HTTP methods (e.g., GET, PATCH, DELETE).
2. Perform an authorized GET request to retrieve a resource (e.g., GET /users/15).
3. Attempt to change the method to PATCH or DELETE on the same resource (e.g., PATCH /users/15 or DELETE /users/15) to check if authorization is enforced.
4. Observe the response to determine if the request was successful or if proper authorization checks were in place.

## Commands

```text
GET /users/15 HTTP/1.1
PATCH /users/15 HTTP/1.1
DELETE /users/15 HTTP/1.1
```
