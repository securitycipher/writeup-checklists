## Use case

GraphQL APIs can be vulnerable to insecure direct object references (IDOR) if they allow users to access objects by supplying arguments that correspond to those objects. This can lead to unauthorized data access, which is critical to address in web application security.

## Steps to test

1. Identify the GraphQL endpoint by sending a universal query to common paths such as /graphql or /api/graphql.
2. Send a query to retrieve a list of products, e.g., 'query { products { id name listed } }'.
3. Analyze the response to identify any missing product IDs that may indicate potential IDOR vulnerabilities.
4. Craft a query to access the details of a missing product by its ID, e.g., 'query { product(id: 3) { id name listed } }'.
5. Observe the response to determine if unauthorized access to the product details is granted.
