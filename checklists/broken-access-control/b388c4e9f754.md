## Use case

The vulnerability was found in a SaaS collaboration platform where different sharing features used separate APIs that trusted user-supplied user IDs without proper verification. This led to unauthorized access to user information through audit logs, which could be exploited by an attacker.

## Steps to test

1. Identify endpoints related to resource sharing in the application.
2. Intercept a request to share a resource and modify the userId parameter to an external user's ID.
3. Send the modified request and observe the response status code.
4. Check the application’s activity history or audit logs to see if the external user's information is exposed.

## Commands

```text
curl -X POST https://example.com/api/share -d '{"userId": "external_user_id"}' -H 'Authorization: Bearer YOUR_TOKEN'
curl -X GET https://example.com/api/audit -H 'Authorization: Bearer YOUR_TOKEN'
```
