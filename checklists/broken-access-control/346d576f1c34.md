## Use case

The application allowed unauthorized access to sensitive resources due to improper access control mechanisms, leading to potential account takeover and exposure of private files.

## Steps to test

1. Identify the target application and its endpoints.
2. Attempt to access user-specific resources without authentication or with a different user's credentials.
3. Monitor the responses to determine if sensitive data is exposed.
4. Test for SQL injection by manipulating input parameters in requests to see if unauthorized data can be retrieved.

## Commands

```text
GET https://example.com/api/user/data HTTP/1.1
GET https://example.com/api/admin/data HTTP/1.1
POST https://example.com/api/login -d 'username=admin&password=wrongpassword'
GET https://example.com/api/files/private HTTP/1.1
```
