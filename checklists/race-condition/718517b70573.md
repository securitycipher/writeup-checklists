## Use case

The vulnerability was found in the Password Reset flow where concurrent requests allowed multiple valid OTPs to be generated for the same session, leading to potential Account Takeover (ATO). This flaw bypassed the rate-limiting and OTP validation mechanisms.

## Steps to test

1. Initiate a password reset request by sending a POST request to the '/forgot-password' endpoint with a valid email address.
2. Simultaneously send multiple POST requests to the same '/forgot-password' endpoint to trigger the OTP generation concurrently.
3. Capture the OTPs returned in the responses of the concurrent requests.
4. Attempt to validate the OTPs by sending a POST request to the '/verify-otp' endpoint with each of the captured OTPs, monitoring for successful validation.

## Commands

```text
POST https://example.com/forgot-password -d 'email=user@example.com'
POST https://example.com/forgot-password -d 'email=user@example.com' (repeat this command multiple times in parallel)
POST https://example.com/verify-otp -d 'otp=123456' (replace 123456 with each captured OTP)
```
