## Use case

The OopsSec Store checkout process allowed a single-use coupon to be redeemed multiple times due to a race condition between reading and updating the coupon usage count. This vulnerability could lead to significant financial loss for the business if exploited.

## Steps to test

1. Set up the OopsSec Store application using 'npx create-oss-store oss-store' and 'npm start'.
2. Reseed the database to reset the coupon usage count with 'npm run db:seed'.
3. Log in to the application using curl to obtain an auth token: 'curl -s -c cookies.txt -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d '{"email":"alice@example.com","password":"iloveduck"}''.
4. Confirm the coupon application endpoint does not consume the coupon by testing with 'curl -s -X POST http://localhost:3000/api/coupon/apply -H "Content-Type: application/json" -H "Cookie: authToken=<your-authToken>" -d '{"code":"FLASHSALE","cartTotal":100}' and ensure the response is consistent.
5. Create a Python script to send 30 concurrent order requests to the '/api/orders' endpoint using the same coupon code.
6. Execute the script to see how many orders are successfully processed.

echo "Token: $TOKEN"

-H "Content-Type: application/json" \

-d '{"code":"FLASHSALE","cartTotal":100}'
