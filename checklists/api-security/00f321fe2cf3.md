## Use case

The application allowed users to change their password without enforcing server-side validation for password length, which could lead to resource exhaustion or service degradation if exploited. This highlights the importance of validating input on the server side to prevent bypassing client-side restrictions.

## Steps to test

1. Navigate to the Change Password feature of the application.
2. Enter a valid password within the allowed limit (e.g., 'Password123').
3. Intercept the request using Burp Suite before it reaches the server.
4. Modify the 'new_password' parameter to exceed the allowed length (e.g., change it to 20 characters).
5. Forward the modified request to the server.
6. Observe the server's response to confirm acceptance of the longer password.

## Commands

```text
POST https://example.com/api/change_password
Content-Type: application/json
{ "new_password": "Password12345678901234567890" }
```
