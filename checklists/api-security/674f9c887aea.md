## Use case

The application allowed users to self-register despite a frontend indication of invite-only access, leading to unauthorized access to sensitive user data. This misconfiguration allowed an attacker to create an account and access the organization’s member roster.

## Steps to test

1. Inspect the application’s frontend for authentication options and identify any hidden registration endpoints.
2. Attempt to create an account directly via the identity provider's API using a POST request to /signup with a new username and password.
3. Complete any email verification process if required.
4. Authenticate the new account through the OAuth flow to obtain an access token.
5. Use the access token to make a GET request to /v1/organizations/{organization_id}/membership to retrieve the organization’s member data.
