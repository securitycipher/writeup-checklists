## Use case

The Jet Admin platform allows users to connect custom domains to their workspaces, but it fails to enforce tenant isolation, allowing an attacker to claim a victim's domain and inject malicious scripts. This vulnerability is critical as it can lead to credential harvesting and session hijacking of legitimate users.

## Steps to test

1. Create a new Jet Admin workspace and connect a custom domain (e.g., app.example.com).
2. Attempt to claim a domain that is already in use by another workspace.
3. If successful, access the sign-in page builder for the claimed domain.
4. Inject a JavaScript payload into the custom scripts/styles field.
5. Save the changes and visit the sign-in page from a different browser or incognito mode.
6. Observe the execution of the injected script in the context of the victim's domain.

## Commands

```text
POST /api/v1/domains HTTP/1.1
Host: jetadmin.io
Content-Type: application/json
Authorization: Bearer <access_token>
{"domain": "app.example.com"}
```
