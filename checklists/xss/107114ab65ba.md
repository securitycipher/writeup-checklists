## Use case

The vulnerability was found in a self-redirect feature that only allowed redirection to URLs containing the host itself. This limitation was exploited to inject JavaScript code, leading to an XSS attack.

## Steps to test

1. Identify a self-redirect URL parameter, such as 'url' in 'https://host.com/nl/redirect?url={payload}'.
2. Attempt to bypass the self-redirect restriction by crafting a payload that includes 'javascript://' followed by a CRLF injection.
3. Use URL encoding to manipulate the payload, such as '%250A' to create a CRLF and '%25250A' to ensure it is processed correctly.
4. Test the crafted URL by clicking the link to see if the JavaScript executes, indicating a successful XSS.

## Commands

```text
https://host.com/nl/redirect?url=javascript://%250A%25250Aalert('XSS');url='.host.com';
```
