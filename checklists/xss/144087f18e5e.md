## Use case

The application improperly handles user input from the URL query parameter, allowing an attacker to inject JavaScript code that executes in the context of the user's session. This can lead to unauthorized actions and data exposure.

## Steps to test

1. Navigate to the search page of the application.
2. Modify the URL to include a crafted query parameter, e.g., /search?q=%3Cimg%20src%3Dx%20onerror%3Dalert(document.domain)%3E.
3. Observe the page displaying the message with the injected content.
4. Verify that the JavaScript executes, confirming the presence of a DOM-based XSS vulnerability.

## Commands

```text
/search?q=%3Cimg%20src%3Dx%20onerror%3Dalert(document.domain)%3E
const q = new URLSearchParams(location.search).get('q') ?? ''; message.innerHTML = `No results for <strong>${q}</strong>`;
<img src=x onerror=alert(document.domain)>
const q = new URLSearchParams(location.search).get('q') ?? '';
const strong = document.createElement('strong');
strong.textContent = q;
message.replaceChildren('No results for ', strong);
```
