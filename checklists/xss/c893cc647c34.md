## Use case

The article discusses hidden parameters in web applications that can lead to XSS vulnerabilities. These parameters are often overlooked by hunters, making them a valuable target for exploitation.

## Steps to test

1. Identify the web application and analyze the network traffic to find hidden parameters that are not visible in the URL.
2. Use tools like Burp Suite to intercept requests and inspect the parameters being sent to the server.
3. Fuzz the identified hidden parameters with common XSS payloads to test for reflected or stored XSS vulnerabilities.
4. Observe the server's response for any reflected payloads or indications of script execution.

## Commands

```text
GET https://example.com/path?hidden_param=<script>alert('XSS')</script>
POST https://example.com/api/endpoint HTTP/1.1
Content-Type: application/x-www-form-urlencoded
hidden_param=<script>alert('XSS')</script>
```
