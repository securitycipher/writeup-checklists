## Use case

The application improperly trusts data from document.referrer, window.name, or window.postMessage, allowing an attacker to inject malicious scripts into the DOM, leading to potential XSS vulnerabilities.

## Steps to test

1. Identify if the application uses document.referrer, window.name, or window.postMessage as input.
2. For document.referrer, create a controlled redirect from your site with a payload in the referrer URL.
3. For window.name, set a payload on your site and navigate to the target site using a method that preserves window.name.
4. For window.postMessage, send a message to the target site and observe if it is written to the DOM without sanitization.
