## Use case

The application allows users to access objects that do not belong to them due to a lack of proper authorization checks, leading to potential account takeover vulnerabilities.

## Steps to test

1. Log in as User A.
2. Proxy your session through Burp Suite.
3. Identify object references in the URL path (e.g., /api/users/1042), query string (e.g., ?user_id=), request body (e.g., {"authorId": 1042}), and headers (e.g., X-User-Id).
4. Modify the object reference to point to another user's ID (e.g., change ?user_id=1042 to ?user_id=1043).
5. Send the modified request and observe if the server returns the object belonging to User B.

## Commands

```text
GET https://example.com/api/users/1042
GET https://example.com/api/users/?user_id=1042
POST https://example.com/api/users {"authorId": 1042}
GET https://example.com/api/users/1043
```
