## Use case

The vulnerability was found in an API endpoint that failed to verify user permissions, allowing an attacker to access another user's admin dashboard by manipulating an HTTP header. This flaw is critical as it exposes sensitive user data and administrative functions.

## Steps to test

1. Intercept the HTTP request to the API endpoint that updates shipping addresses using Burp Suite.
2. Identify the parameter that contains the user ID in the request.
3. Change the user ID parameter to another user's ID (e.g., from id=10842 to id=10843).
4. Send the modified request and observe the server's response.

## Commands

```text
GET https://example.com/api/update_address?id=10843 HTTP/1.1
Host: example.com
Authorization: Bearer <token>
```
