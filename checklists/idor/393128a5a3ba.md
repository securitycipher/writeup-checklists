## Use case

The vulnerability was found in an API endpoint that allowed access to user data by simply changing the user ID in the request. This is critical as it can lead to unauthorized data exposure for all users.

## Steps to test

1. Log in to the application and capture the request to /api/sessions/login.
2. Observe the response and note the user ID assigned to your account.
3. Send a GET request to /api/users/{id} using Burp Repeater, replacing {id} with the user ID you noted.
4. Change the user ID to the previous one (e.g., if your ID is 842, try 841) and resend the request.
5. Check the response for any user data that should not be accessible.

## Commands

```text
POST /api/sessions/login HTTP/1.1
GET /api/users/842 HTTP/1.1
GET /api/users/841 HTTP/1.1
```
