## Use case

The booking lookup feature was vulnerable due to improper handling of the surname parameter, allowing an attacker to bypass authorization checks and access sensitive passenger information using a wildcard character.

## Steps to test

1. Open Burp Suite and intercept the request to the booking lookup endpoint.
2. Modify the 'surname' parameter in the request body from a valid surname to '%'.
3. Send the modified request to the server.
4. Observe the response for sensitive passenger information being returned.
5. Test other wildcard inputs like 'D%' and '%AL' to confirm the pattern matching behavior.
6. Verify that the application does not reject these inputs as invalid.
