## Use case

Web cache poisoning occurs when an unkeyed input influences the cached response, allowing an attacker to serve malicious content to all users accessing the page. This vulnerability is critical as it affects every visitor to the cached page, not just the attacker.

## Steps to test

1. Confirm that the target page is cached by checking cache headers such as X-Cache, Age, and CF-Cache-Status.
2. Identify unkeyed inputs that can influence the response, such as specific headers.
3. Craft a request with a malicious unkeyed header that alters the response.
4. Send the crafted request and verify that the response is cached.
5. Access the page without the malicious header and check if the poisoned response is served.

## Commands

```text
GET https://example.com/page HTTP/1.1
Host: example.com
X-Custom-Header: malicious_value
```
