## Use case

The application improperly caches responses based on unvalidated client-supplied headers, allowing an attacker to poison the cache and serve malicious content to subsequent users. This flaw can lead to significant security risks, including data leakage and user impersonation.

## Steps to test

1. Identify the target application and its caching mechanism.
2. Inspect the response headers of a cacheable endpoint, such as the homepage.
3. Look for any unkeyed headers that influence the response, such as 'X-Custom-Header'.
4. Craft a request with a modified value for the unkeyed header and observe the response.
5. Verify if the modified response is cached by making a request without the unkeyed header.
6. Check if the cached response reflects the changes made in the previous step.

## Commands

```text
curl -H 'X-Custom-Header: malicious_value' -X GET https://example.com/homepage
curl -X GET https://example.com/homepage
```
