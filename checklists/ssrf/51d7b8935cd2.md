## Use case

The vulnerability involved an SSRF filter that only validated the initial URL submitted by the user, failing to check the final URL after a 301 redirect. This oversight allowed attackers to bypass security measures and access internal resources.

## Steps to test

1. Identify a web application that accepts user-supplied URLs.
2. Submit a URL that triggers a 301 redirect to an internal resource (e.g., http://example.com/redirect?url=http://internal.example.com).
3. Observe if the application fetches the content from the internal resource instead of the original URL.
4. Check the response to confirm that the internal resource is accessible despite the SSRF filter.

## Commands

```text
curl -X GET 'http://example.com/redirect?url=http://internal.example.com'
```
