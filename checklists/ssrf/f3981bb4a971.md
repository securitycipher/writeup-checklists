## Use case

The vulnerability arises when the server fetches a URL provided by the user, allowing an attacker to direct the server to internal resources, such as cloud metadata endpoints, which could expose sensitive information.

## Steps to test

1. Identify features in the application that accept user-supplied URLs, such as PDF generators or image renderers.
2. Provide a URL that points to a cloud metadata endpoint (e.g., http://169.254.169.254/latest/meta-data/).
3. Monitor the server's response to confirm if it retrieves data from the internal resource.
4. Check for any sensitive information returned in the response.

## Commands

```text
curl -X GET 'http://example.com/pdf-generator?url=http://169.254.169.254/latest/meta-data/'
curl -X GET 'http://example.com/image-renderer?url=http://169.254.169.254/latest/meta-data/'
```
