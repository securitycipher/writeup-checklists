## Use case

The application allowed an attacker to change a victim's email address without verification by exploiting a mass assignment vulnerability in the account settings page. This led to account takeover (ATO) as the attacker could log in using the victim's email and their own password.

## Steps to test

1. Navigate to the account settings page of the application.
2. Intercept the request for the profile update form using a proxy tool.
3. Modify the 'email' parameter in the request body to the victim's email address.
4. Send the modified request.
5. Log out of the attacker account.
6. Attempt to log in using the victim's email and the attacker's password.

## Commands

```text
POST /update-profile HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <attacker_token>
{ "email": "victim@example.com", "other_field": "value" }
```
