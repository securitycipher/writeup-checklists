## Use case

The API Gateway failed to properly handle path traversal sequences, allowing access to internal endpoints that should be restricted. This vulnerability could lead to exposure of sensitive internal services and data.

## Steps to test

1. Identify a public endpoint on the API Gateway, e.g., /match/ad/apps/rec/discover.
2. Append traversal sequences to the endpoint, such as ../%0d%0a/../../_/metrics.
3. Send a GET request to the modified endpoint.
4. Observe the response; if it returns HTTP 200 OK, internal resources may be exposed.
