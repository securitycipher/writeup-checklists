## Use case

The vulnerability allows an attacker to gain unauthorized Owner access to a victim's organization by tampering with the role_id parameter during the invitation process, leading to persistent control over the victim's organization without their consent.

## Steps to test

1. Log in as Account A (attacker) and create a new organization.
2. Open the invite panel and invite Account B (victim) as Administrator.
3. Intercept the request and change the role_id from 2 (Administrator) to 1 (Owner).
4. Forward the modified request and confirm that Account B is added as Owner without any validation error.
5. Log in as Account B and create a new organization.
6. Log back into Account A and check the dashboard to see if Account B's new organization appears with Owner privileges.

## Commands

```text
POST /invite HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <token>
{ "email": "victim@example.com", "role_id": 1 }
```
