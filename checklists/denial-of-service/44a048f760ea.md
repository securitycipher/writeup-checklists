## Use case

The vulnerability existed in the /drafts.json endpoint of a Discourse forum, where oversized payloads could be saved as drafts without proper validation, leading to server slowdowns and potential denial of service for all users.

## Steps to test

1. Log into a test account on the target Discourse instance.
2. Intercept a draft request at POST /drafts.json using Burp Suite.
3. Replace the draft content with an oversized payload (e.g., 800,000 characters).
4. Submit the request and observe the 502 error response while confirming the draft was saved.
5. Create additional unique drafts with the same oversized payload using different keys to avoid conflicts.
6. Send all drafts in sequence or parallel and monitor the response times.

## Commands

```text
POST /drafts.json HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: [length_of_payload]
{"draft":"[800,000 characters here]"}
```
