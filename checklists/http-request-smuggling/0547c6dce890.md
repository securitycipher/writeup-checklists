## Use case

The vulnerability was identified in the interaction between a front-end proxy and a back-end origin server, where they disagreed on the boundaries of HTTP requests. This misalignment allowed for potential request smuggling attacks, which could lead to various security issues.

## Steps to test

1. Send an HTTP request with both 'Content-Length' and 'Transfer-Encoding' headers to the target server.
2. Observe the response for any unexpected behavior or errors, particularly a 404 error that seems inconsistent with the request.
3. Analyze the server's response to determine if the request was processed differently by the front-end and back-end systems.
4. Use a tool like Burp Suite to manipulate the request and test different combinations of headers to confirm the request smuggling vulnerability.

## Commands

```text
GET / HTTP/1.1
Host: example.com
Content-Length: 13
Transfer-Encoding: chunked

0

GET /admin HTTP/1.1
Host: example.com
```
