## Use case

The application incorrectly uses the Host header to generate password reset links, allowing an attacker to redirect the reset link to their own server, leading to potential account takeover.

## Steps to test

1. Identify a web application that uses the Host header to generate password reset links.
2. Trigger the password reset functionality to receive a reset email.
3. Intercept the request using a proxy tool and modify the Host header to an attacker-controlled domain (e.g., attacker.com).
4. Send the modified request to the server.
5. Check the email received for the reset link pointing to the attacker-controlled domain.
6. Click the link to verify that it leads to the attacker's server with the victim's reset token.

## Commands

```text
curl -X POST -H 'Host: attacker.com' https://example.com/request-password-reset
reset_link = f"https://{request.headers['Host']}/reset?token={token}"
```
