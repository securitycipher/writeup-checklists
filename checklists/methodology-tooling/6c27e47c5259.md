## Use case

The article emphasizes the importance of understanding application architecture and business logic to identify vulnerabilities, particularly in authorization and access control scenarios. This matters because many vulnerabilities exist not in obvious endpoints but in the relationships and permissions between users and objects.

## Steps to test

1. Identify the application and its key functionalities such as user roles and object management.
2. Create multiple test accounts with different roles (e.g., normal user, admin).
3. Map the permissions and actions each account can perform on shared resources.
4. Test access control by attempting to access or modify resources owned by other users.
