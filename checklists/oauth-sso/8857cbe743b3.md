## Use case

The OAuth 2.0 flow was vulnerable due to improper validation of redirect URIs, allowing attackers to obtain tokens for arbitrary email addresses without ownership verification, leading to full account takeover.

## Steps to test

1. Identify the OAuth authorization endpoint of the target application.
2. Attempt to register a redirect URI that includes common bypass patterns such as subdomain confusion or regex escape failures.
3. Initiate the OAuth flow by sending a request to the authorization endpoint with the crafted redirect URI.
4. Monitor the response to see if the authorization code is redirected to your controlled URI.
5. If successful, exchange the authorization code for an access token using the token endpoint.
