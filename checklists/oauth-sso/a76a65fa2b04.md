## Use case

OAuth 2.0 implementations often suffer from vulnerabilities due to improper handling of authorization flows, particularly in the context of state validation and redirect URI manipulation. These flaws can lead to unauthorized access and account takeover.

## Steps to test

1. Initiate an OAuth flow and capture the authorization code.
2. Check if PKCE is enforced by verifying the presence and validation of the code_verifier.
3. Test the state parameter for predictability and validation on callback.
4. Attempt redirect URI manipulation by using variations like 'https://attacker.com' or 'https://trusted.com@attacker.com'.
5. Verify access token storage and check for leakage in browser history or server logs.
6. Test refresh token handling for secure storage and proper revocation on logout.

```text
https://trusted.com/callback/

☐ PKCE enforced and code_verifier actually validated
☐ state present, unpredictable, session-bound, validated
☐ redirect_uri strictly matched (no wildcards / subdomain tricks)
☐ Access tokens: storage, leakage, lifetime, audience validation
☐ Refresh tokens: rotation, reuse detection, revocation on logout
☐ Scopes enforced server-side, not just requested client-side
☐ Account linking requires re-authentication / real identity proof
☐ Token validation: iss, aud, exp, signature
☐ Client authentication not exposed or weak
☐ No deprecated implicit flow in use
```
