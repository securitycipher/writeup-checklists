## Use case

The vulnerability lies in the handling of the redirect_uri parameter in OAuth flows, where servers only check if the URI starts with a trusted domain rather than matching it exactly. This allows an attacker to redirect the authorization code to a domain they control, potentially leading to account takeover.

## Steps to test

1. Obtain the authorization URL for the OAuth flow.
2. Modify the redirect_uri parameter to a variant of the trusted domain that you control.
3. Initiate the authorization request using the modified URL.
4. Check if the server issues the authorization code to your controlled domain.

## Commands

```text
https://AUTH_TARGET/authorize?client_id=APP_ID&redirect_uri=https://ATTACKER_DOMAIN/callback&response_type=code
```
