## Use case

The article discusses the discovery of over 100 zero-day vulnerabilities in open source software, particularly focusing on SQL injection vulnerabilities in widely used geospatial projects. These vulnerabilities can lead to unauthorized access to sensitive data, impacting critical infrastructure.

## Steps to test

1. Identify a geospatial project that uses a database backend.
2. Locate endpoints that accept user input, such as search or filter parameters.
3. Manipulate the input parameters to include SQL injection payloads, such as ' OR '1'='1' --.
4. Observe the application's response for any unexpected data exposure or errors indicating a successful injection.

## Commands

```text
agentgg scan ./src -t sql-injection -o ./out
agentgg scan ./src --diff origin/main...HEAD -o ./out
preamble       git setup, agentic auto-exclude
recon          one LLM survey of the project
preconditions  regex or semgrep census, then LLM gate
agents         batched agent pool, the core scan
validate       re-check each finding, is it real
score          CVSS severity per finding
dedup          collapse same-root-cause findings
report         write markdown, no LLM
npm install -g agentgg
agentgg init
agentgg init --provider anthropic     # paste an sk-ant-api... key, or a Claude Pro/Max OAuth token
agentgg init --provider openrouter    # then paste your key; GLM 5.2 is the default model
agentgg scan ./src -o ./out
agentgg view ./out
# or scan and boot the UI in one step:
agentgg scan ./src -o ./out --serve
agentgg scan ./src -t sql-injection -o ./out                 # one agent by slug
agentgg scan ./src -t base/injection/ -o ./out               # a whole category
agentgg scan ./src -t ./my-agents/ -o ./out                  # your own agents
agentgg scan ./src --only "src/api/**" --exclude "**/migrations/**" -o ./out
```
