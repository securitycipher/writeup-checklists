## Use case

The vulnerable feature was the 'Advanced Employee Search' modal that allowed users to input custom filters. This was critical as it led to an unauthenticated NoSQL Injection, resulting in a complete database takeover.

## Steps to test

1. Navigate to the 'Advanced Employee Search' modal on the web application.
2. Input a custom filter in the search box, such as 'Department = Engineering AND 1=1'.
3. Observe the response for any unexpected data exposure or errors.
4. Modify the filter to include NoSQL injection payloads, such as 'Department = Engineering AND { $ne: null }'.
5. Check if the application returns data from the database that should not be accessible.

## Commands

```text
GET https://example.com/advanced-search?filter=Department%3DEngineering%20AND%201%3D1
GET https://example.com/advanced-search?filter=Department%3DEngineering%20AND%20%7B%20%24ne%3A%20null%20%7D
```
