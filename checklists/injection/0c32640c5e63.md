## Use case

The application was vulnerable to SQL injection, which allowed an attacker to bypass authentication and potentially execute operating system commands. This vulnerability chain highlights the importance of understanding how multiple vulnerabilities can interact to escalate an attack.

## Steps to test

1. Perform reconnaissance to identify the login functionality at /login.
2. Capture the login request and analyze the POST parameters for username and password.
3. Test for SQL injection by modifying the username and password inputs with controlled SQL syntax.
4. Confirm SQL injection by observing changes in authentication logic based on the modified input.
5. After successful authentication, inspect the session cookies and IDs to verify access to the dashboard.
6. Explore the dashboard for administrative functions that may lead to command injection.
