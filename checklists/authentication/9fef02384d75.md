## Use case

The application improperly validates JWT tokens, allowing an attacker to forge tokens and gain unauthorized access to restricted functionalities, such as admin endpoints.

## Steps to test

1. Identify JWT usage by looking for 'Authorization: Bearer <JWT>' in requests.
2. Decode the JWT using Burp Suite or another decoder to inspect its claims.
3. Check the JWT header for the 'alg' value and test if the server accepts an unsigned token with 'alg': 'none'.
4. Modify a security-sensitive claim in the JWT payload (e.g., change 'role': 'user' to 'role': 'admin').
5. Send a request to a restricted endpoint (e.g., GET /admin/dashboard) using the original token and then the modified token.
6. Verify if the server grants access with the modified token.
