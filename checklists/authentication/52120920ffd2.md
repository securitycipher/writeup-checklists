## Use case

The registration flow of the application allowed users to bypass CAPTCHA verification by using arbitrary email domains instead of well-known public email providers. This vulnerability could lead to automated account creation and potential abuse of the platform's resources.

## Steps to test

1. Send a POST request to /api/account/create with a well-known email provider (e.g., user@gmail.com) and observe the 403 Forbidden response.
2. Modify the email address to use an arbitrary domain (e.g., user@RandomDomain.com) in the same POST request.
3. Send the modified request and check if the account is created without CAPTCHA verification.
4. Repeat the test with multiple random domains to confirm consistent bypass behavior.
