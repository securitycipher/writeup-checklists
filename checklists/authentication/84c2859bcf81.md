## Use case

The vulnerability existed in the password reset flow where the server blindly trusted the email parameter, allowing an attacker to reset any user's password using a valid token. This flaw could lead to account takeover without any victim interaction.

## Steps to test

1. Go to the Forgot Password page and enter your own email address.
2. Retrieve the reset email and open the reset link.
3. Before submitting the new password, intercept the request using Burp Suite.
4. Modify the email parameter in the request to a different registered user's email address.
5. Forward the modified request to the server.
6. Attempt to log in with the victim's email and the new password you set.

## Commands

```text
email=attacker@gmail.com&token=abc123&new_password=NewPass@123
email=victim@gmail.com&token=abc123&new_password=NewPass@123
```
