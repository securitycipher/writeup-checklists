## Use case

The application allowed password resets and changes without any authentication, enabling an attacker to take over any employee account by knowing just the username. This vulnerability could lead to unauthorized access to sensitive internal data.

## Steps to test

1. Identify a target username on the application.
2. Send a POST request to /api/v1/auth/reset-password with the username in the request body.
3. Receive the default password in the response.
4. Send a POST request to /api/v1/auth/change-password with the username, old password (default), and a new password of your choice.
5. Log in using the username and the new password to confirm account takeover.
