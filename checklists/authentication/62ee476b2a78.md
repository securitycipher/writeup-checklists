## Use case

The vulnerability involves the Change Email feature in an application using Google OAuth, allowing an attacker to take control of an account by changing the email to that of a victim without any verification, leading to potential account takeover.

## Steps to test

1. Create an account using Google OAuth with an email you control (e.g., attacker@example.com).
2. Navigate to account settings and use the Change Email feature to change the email to the victim's email (e.g., victim@example.com).
3. Confirm that the email change is successful without any verification.
4. Attempt to register a new account using the victim's email (e.g., victim@example.com) and observe that it indicates the email is already in use.
5. Use the password reset functionality to reset the password for the victim's email and log in.
6. Verify that you can log in to the account using both the victim's credentials and the original Google OAuth account.

## Commands

```text
POST https://example.com/api/change-email
Body: { 'new_email': 'victim@example.com' }
POST https://example.com/api/register
Body: { 'email': 'victim@example.com', 'password': 'newpassword' }
POST https://example.com/api/reset-password
Body: { 'email': 'victim@example.com' }
```
