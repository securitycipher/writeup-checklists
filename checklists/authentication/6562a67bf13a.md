## Use case

The password reset form allowed unauthenticated access to the database through SQL injection vulnerabilities in the email parameter. This was critical as it could lead to unauthorized data access without user authentication.

## Steps to test

1. Identify the password reset endpoint: POST /index.php?option=com_chronoforms&chronoform=reset_password&event=submit.
2. Send a POST request with a crafted email parameter: email=' OR 1=1-- to test for SQL injection.
3. Observe the response for differences in HTTP status codes to confirm SQL execution: HTTP 200 for valid conditions and HTTP 302 for invalid.
4. Iterate through boolean queries to extract database information, starting with: Is the first character of the database version '8'?
5. Use non-matching email addresses to avoid triggering actual password reset emails.
